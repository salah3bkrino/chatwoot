1. مقدمة الـ Webhooks

1.1 ما هي الـ Webhooks؟

الـ Webhook هو رابط HTTP يرسل بيانات من Chatwoot إلى نظام آخر عند حدوث حدث معين. مثل الـ "تنبيهات الفوري" للأنظمة الخارجية.

1.2 كيف تعمل؟

حدث يحدث في Chatwoot → تحقق الشروط → إرسال POST request إلى الـ Webhook URL → النظام الخارجي يستقبل البيانات ويعالجها → (اختياري) إرسال رد مجدداً لـ Chatwoot

1.3 الأحداث المتاحة

الحدث متى يُطلق البيانات المرسلة
conversation.created محادثة جديدة معرّف المحادثة، العميل، الوصل
message.created رسالة جديدة محتوى الرسالة، المرسل، الوقت
conversation.status_changed تغيير حالة الحالة الجديدة، المحادثة
conversation.updated تحديث المحادثة البيانات المحدثة
agent.updated تغيير الوكيل/الفريق معرّف الوكيل، الفريق

1.4 الفوائد

  • التكامل التلقائي: الربط بين الأنظمة بدون تدخل يدوي
  • تحديثات فورية: بيانات محدثة في الوقت الفعلي
  • عمليات جديدة: أتمتة إجراءات معقدة
  • تقليل الأخطاء: لا نسخ يدوي للبيانات

2. إعداد Webhook

2.1 خطوات الإعداد

  1. اذهب إلى Settings > Webhooks
  2. انقر Create Webhook
  3. أدخل Webhook URL (رابط النظام الخارجي)
  4. اختر Events التي تريد الاستماع لها
  5. حدّد الشروط (اختياري)
  6. أضف Headers مخصصة (مثل: Authentication)
  7. اضغط Create

2.2 مثال: Webhook بسيط

مثال: إرسال بيانات إلى CRM
URL: https://api.mycrm.com/chatwoot/webhooks
Events: conversation.created, message.created
Headers:
Authorization: Bearer YOUR_TOKEN
X-API-Key: secret123

2.3 البيانات المرسلة (Payload)

مثال: conversation.created

{ "event": "conversation.created", "id": 123456, "conversation": { "id": 789, "status": "open", "inbox_id": 1, "user": { "id": 456, "name": "Ahmed", "email": "ahmed@example.com", "phone": "+201000000000" }, "created_at": "2026-07-19T10:30:00Z" } }

مثال: message.created

{ "event": "message.created", "id": 123457, "message": { "id": 999, "conversation_id": 789, "content": "شكراً على الرد", "message_type": "incoming", "sender": { "id": 456, "name": "Ahmed" }, "created_at": "2026-07-19T10:35:00Z" } }

5. الأمان وأفضل الممارسات

5.1 أمان الـ Webhook

التحقق من التوقيع (Signature Verification)

كل webhook يأتي مع توقيع للتأكد من أنه من Chatwoot:

  • Header: X-Chatwoot-Signature
  • الخوارزمية: HMAC-SHA256
  • الاستخدام: التحقق في الطرف المستقبل
مثال: التحقق من التوقيع (Node.js)
const crypto = require('crypto'); const signature = req.headers['x-chatwoot-signature']; const secret = process.env.CHATWOOT_SECRET; const payload = req.rawBody; const hash = crypto .createHmac('sha256', secret) .update(payload) .digest('hex'); if (hash === signature) { console.log('✅ توقيع صحيح'); } else { console.log('❌ توقيع غير صحيح'); }

5.2 أفضل الممارسات

  • ✅ استخدم HTTPS فقط (مشفر)
  • ✅ تحقق من التوقيع دائماً
  • ✅ استخدم رموز مصادقة قوية
  • ✅ سجّل جميع الـ Webhooks
  • ✅ اختبر قبل التفعيل
  • ✅ راقب الأخطاء والفشل
  • ❌ لا تضع بيانات حساسة في URL
  • ❌ لا تنسَ تحديث الـ URLs

5.3 معالجة الأخطاء

الخطأالسببالحل
Timeoutالنظام الخارجي بطيءأضف timeout، أو عالج بشكل غير متزامن
404 Not FoundURL غير صحيحتحقق من الـ URL
401 Unauthorizedمشكلة في المصادقةتحقق من الرموز والـ Headers
500 Internal Errorمشكلة في النظام الآخراتصل بـ support النظام الآخر

5.4 إعادة المحاولة (Retries)

إذا فشل الـ Webhook، Chatwoot يحاول مجدداً:

  • عدد المحاولات: حتى 5 مرات
  • الفاصل الزمني: 30 ثانية، دقيقة، 5 دقائق، إلخ
  • إذا فشل: تُرسل إشعار للـ Admin

  2. اختر الـ Webhook
  3. انقر Logs أو History
  4. اعرض:
    - الحدث التي تم إرسالها
    - الرد من النظام الآخر
    - الأخطاء (إن وجدت)

7. التطوير المتقدم

7.1 Webhook مخصص (Custom Webhook)

مثال: Node.js Server يستقبل Webhooks
const express = require('express'); const app = express(); app.post('/webhook', (req, res) => { const { event, conversation, message } = req.body; if (event === 'message.created') { console.log(`رسالة جديدة: ${message.content}`); // معالجة الرسالة هنا } res.json({ success: true }); }); app.listen(3000);

8. استكشاف الأخطاء

8.1 المشاكل الشائعة

المشكلة: Webhook لا يُطلق
✅ الحلول:
- تحقق من أن الـ Event محدد بشكل صحيح
- تحقق من أن الشروط محققة
- اختبر الـ Webhook يدويّاً
- انظر في السجلات للأخطاء
- تأكد من أن الـ URL يعمل
المشكلة: Webhook يفشل بـ 401 Unauthorized
✅ الحلول:
- تحقق من الرموز (Tokens) والمفاتيح
- تحقق من صيغة Authorization Header
- تأكد من عدم انتهاء صلاحية الرمز
- جدد الرمز إذا لزم الأمر
المشكلة: البيانات لا تصل كاملة
✅ الحلول:
- تحقق من Content-Type (application/json)
- تحقق من صيغة JSON الداخلة
- استخدم Logs لرؤية البيانات الفعلية
- اختبر مع أداة مثل Postman
